# Meal Story Poster

真实照片 → 1080×1440 PNG 海报 + 一份 `发布文案.txt`。使用内置绿叶背景、手写中文字体、黄色笔刷条、奶油白卡片和食材装饰。默认顶部名称为「三人行托管中心」，用户指定名称时写入 `brand.name`，每页完整显示，且比栏目标题醒目。

脚本在本 Skill 目录运行，需要 Node.js >=22 和 `npm ci`。运行无需联网或生图服务。结果自动放入本 Skill 的 `outputs/` 下独立批次，不询问输出位置，不自动全局安装。

## 默认交付要精简

标准九图批次**总共四个文件**，包括隐藏文件在内：

```text
01_综合海报.png
02_备料海报.png
03_餐食海报.png
发布文案.txt
```

- 五类文案写在同一 TXT，以中文平台标题分隔；用户只选部分平台时只写相应部分。
- 不默认生成 HTML、预览拼图、逐平台 TXT、MD、审核 JSON，也不建立隐藏内部目录。不是将文件藏起来，而是不写这些文件。
- 事实、裁切、来源、排版与隐私检查在内存中完成，结果由命令返回，Codex 阅读并简要汇报。检查失败不能当作生成成功。
- 只在用户明确要求保留任务记录、事后完整校验或公开导出时，添加 `--keep-state`，额外保存**一个** `任务状态.json`。普通出图不启用。状态包含输入和审核信息，不作为宣传素材。
- 交付结果文件夹和汇总文案链接即可，必要时直接展示海报；不要求用户管理技术文件。旧批次不自动删除。

## 推荐输入

```text
使用 meal-story-poster，读取 /绝对路径/餐食照片。
顶部机构名称：三人行托管中心。
先列出分类和待确认菜名，确认后生成海报及五类文案。
九图时综合页两排四列、备料页四列加说明区、成品页五图 3+2，汤品放成品页。
真实照片铺满卡片；日期未核实不写“今日”。
自动保存到 Skill outputs，只留下海报和一份文案，不生成其它记录。
```

更多字段见 [输入指南](references/input-guide.md)。已确认的分类、菜名直接沿用，不因调整版式重复询问。日期和门店缺失不阻断中性草稿。

## 素材与事实边界

实际查看用户的 JPG/PNG 原图后提出建议，不能只看文件名猜菜名。1～30 张；无可靠看图能力时不声称识别完成。建议状态先是 needs-confirmation，只有用户明确确认后才能填写 verified；AI 不能代签许可、审核人或批准。

用户上传的成品海报只作视觉参考，不能裁出其中食物冒充机构原图，也不能照搬宣传语。读 [参考分析](references/reference-analysis.md) 和 [视觉规范](references/visual-guidelines.md)。照片等比缩放，食物近景默认 cover，必要时使用 contain；不拉伸、不生成式重画。汤不确定时叫「汤品」，肉种未核实不暗示猪肉，不自动建立原料成品配对。

日期未核实不写「今日」，只有核实且确为当前日期才可使用；跨日使用「近期」。不从照片推断新鲜度、采购、营养、口味、儿童喜好或经营保证。用餐场景 D 的权限规则见 [事实与隐私](references/content-policy.md)，未通过则跳过，其他页面继续。

## 执行

1. `node scripts/meal-story-poster.mjs inspect --input /照片目录`，检查格式、重复、尺寸和解码情况。
2. 看图，必要时写建议 analysis.json；`prepare --input /照片目录 [--analysis /建议文件]` 返回 content.json 路径。依据用户确认编辑分类和名称，未确认日期、许可保持原状态。字段见 [数据契约](references/data-contract.md)。
3. `node scripts/meal-story-poster.mjs build --input /照片目录 --content /content.json`。默认生成新批次，拒绝覆盖非空目录；返回 output、posters、copy、passed、errors 和 warnings。普通生成省略 `--keep-state`。
4. 阅读命令返回的检查结果，逐页打开真实 PNG 对照原图与参考，核对标题、中文、照片裁切、固定行列、标签及所有素材去向。汤品由 C 承载，不能默默漏图。自动检查不能代替看图。
5. 交付海报和汇总文案。文案语气见 [文案规范](references/copy-guidelines.md)。build 始终生成草稿，不推断已获发布许可。

## 可选完整复核与公开导出

需要这条流程时才读 [数据契约的批准部分](references/data-contract.md#人工批准与公开导出)。生成时加 `--keep-state` 保留一个状态文件；后续 `validate --output /批次` 可完整核对原图、事实和成品。未保留状态时 validate 只检查成品文件，必须标注 `verification=files-only`，不能据此批准公开导出。

明确批准具体产物后才能 `export --output /批次 --approval /人工批准.json --destination /新公开目录`；批准需匹配 validate 返回的 bundleDigest、渠道、用途和实际审核时间。公开资格仍要求真实权限与逐图裁切审核，不自主填写 true。公开导出只复制海报、汇总文案和脱敏清单，不是平台发布。旧 private/.internal 批次兼容验证，不必为兼容新版本修改历史文件。

`npm test` 验证文件数量、事实、裁切、授权、篡改和失败路径；`npm run demo` 使用明确标注的合成几何图，不能冒充真实餐食。素材来源见 [内置素材](references/asset-prompts.md)。
