# P0 产品规则

依据用户提供《三人行托管中心｜AI 餐食图文 Skill 设计与开发规格 v1.1》（2026-10-16）整理。原文中的目录、脚本名、日期和九图分析属于目标或示例，不是已存在文件或已核实业务事实。

| 可用的已确认分类照片 | 默认页面 |
|---|---|
| 备料 ≥2 且成品 ≥2 | A 综合页 + B 备料页 + C 成品页 |
| 仅成品 | C；1 张也可生成大卡 |
| 仅备料 | B；1 张也可生成大卡 |
| 两类都有、任一类仅 1 张 | A，不复制照片凑三页 |
| 另有启用且通过人工权限核验的场景 | 增加 D |
| 只有合格场景 | D |
| D 未启用、无素材或权限不合格 | D skipped，无空白占位，不影响其他页面 |
| 没有确认分类的可用照片 | 输出审核原因与失败 QA，先完成分类，不猜测内容出图 |

`output.templates` 可显式选择任意模板；不满足素材或权限要求仍跳过。A 在 C 同时生成时采用最多 4 张备料、4 张成品，超出素材由详情页承载并记录 deferredAssetIds；只选 A 时最多保留 5 张成品；B/C 每页最多 6 张，超过时顺序分页。跨页复用封面素材是正常的，单页内不重复同一哈希。没被选中的照片在 warnings 中列明。

D 的 P0 能力是严格启用/跳过判断及基础单图环境页；独立精修、多图场景、自动人脸识别、裁切匿名化留待 P1。任何类别照片的已知未授权人员或敏感信息风险都不能通过改分类绕过。

默认无需指定输出目录，prepare/build 在 Skill 的 outputs 下自动新建独立批次，返回实际路径。正常九图 build 仅保存 3 张中文海报和一份 `发布文案.txt`，总共 4 个文件，不含隐藏文件或目录。D 启用时增加 `04_用餐海报.png`，分页用 `_02` 后缀；只有明确设置 JPG 才额外保存 JPG。

五类文案汇总到一个 TXT；不默认生成逐平台 TXT、MD、HTML、预览拼图、素材清单、渲染清单、review、warnings 或 QA 文件。检查在内存执行，通过命令返回结果，不向用户留下技术文件。

需要事后完整事实复核或公开导出时才用 `build --keep-state`，将输入指纹、事实快照与渲染记录合为一个 `任务状态.json`，不另外生成报告。状态包含内部路径和权限资料，不是发布素材。默认不保留；旧 private/.internal 批次仍可 validate/export，不自动改动历史目录。

无状态批次的 validate 只检查成品文件，返回 `verification=files-only`、公开资格 false；有状态时返回 full，核对源图指纹、事实、文案和成品字节。验证不新增文件。公开导出仍需独立人工批准与摘要。

内存渲染记录逐页包含 generated/skipped/failed、原因、来源 ID、延后至详情页的 ID、尺寸、裁切范围、图框铺满率和公开资格。build 始终是 draft，QA 失败不会伪装成成功。返回码：0 为命令完成（build/validate 的 QA 通过），2 为 QA 未通过，1 为输入/环境/授权错误。
