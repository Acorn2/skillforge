# 输入指南

## 最少输入

```text
使用 meal-story-poster，读取 /绝对路径/照片目录。
顶部机构名称：三人行托管中心。
先让我核对照片分类和菜名，再生成内部海报草稿与五类文案。
```

机构名称是每页顶部最大的文字，不是某一道菜的名称。用户不提供时采用当前默认「三人行托管中心」，不为了询问默认值阻断工作。用户指定其他机构时，在 `brand.name` 写入实际名称，所有页面和文案统一替换，不能残留默认品牌。不要根据参考图片自行给另一家机构改名。

照片路径可以来自本地文件夹或用户明确提供的独立原图。1 张成品图只做 C；有备料与成品时按数量选择 A/B/C。上传的已完成海报是设计参考，不是其中每盘食物的原始素材。

## 完整输入示例

```text
请使用 meal-story-poster。
照片目录：/绝对路径/餐食照片
机构名称：三人行托管中心
顶部品牌区：每张图都完整显示机构名称，深绿底、浅色大字。
页面风格：浅黄色页面标题条、奶油白圆角卡片；备料绿标，成品橙标。
页面：按素材自动选择综合、备料和成品页。
日期：未核实，暂不填写，不要写“今日”。
托管点：暂不填写。
菜名：先看原图列出建议，未确认的使用中性名称。
文案：朋友圈、家长群、小红书、视频标题、视频描述。
只生成内部草稿，结果自动保存到该 Skill 的 outputs 中。
```

日期和门店是可选事实，不需要用户凑齐才能做中性草稿。用户确认日期时同时设置 dateVerified；确认门店时核对 locationVerified、siteId 与素材来源。用户明确给出菜名时只确认其对应照片，不扩展成采购、口味、营养和儿童喜好结论。

## 输入到成图的对应

| 用户输入 | 程序字段 / 行为 |
|---|---|
| 机构名称 / 顶部名称 | `brand.name`，每页顶部居中、完整显示，五类文案同名 |
| 综合 / 备料 / 成品 | `output.templates`；无明确选择时 auto |
| 日期 / 是否同日 | `record.date`、`dateVerified`、`scope`，与拍摄记录冲突时中性降级 |
| 托管点 | `brand.locationName`、`locationVerified`、`siteId`，并核对每张图 siteId |
| 食材 / 菜名 | 对应 asset 的 category/categoryStatus、label/labelStatus |
| 只生成某渠道 | `copy.targets`，默认五类 |
| 输出位置未填写 | 自动创建本 Skill `outputs/` 下的独立批次，交付实际链接 |
| 网页 GPT 成品图 | 仅分析品牌层级、颜色、布局，不导入其中的食物图或宣传断言 |

输出前核对三层文字：机构名称 → 页面栏目 → 食材/菜名标签。机构名不能省略、错字、截断或比页面标题更小；“今日”不能仅因参考图里有就保留。

## 参考版式的默认行为

无需再指定风格文件或输出路径。默认使用内置绿叶背景、白色手写机构名、黄色笔刷条、奶油白圆角卡、绿/橙白边标签与装饰插画。餐食近景等比裁边铺满；需完整保留某张照片时说明「这张使用 contain」。标准九图综合页两排四列，汤品放在成品页 3+2 中；整组不漏图。用户已确认过的分类与菜名直接沿用，不因调整版式重复询问。

## 结果怎么取用

默认结果文件夹仅有中文海报与一份发布文案.txt，五类文案以中文标题分隔。标准九图总共 4 个文件，没有 HTML、隐藏内部目录或 JSON 报告。只有明确要求保留任务记录或需要事后完整复核时，才用 --keep-state 额外保存一个任务状态.json。旧批次不自动删除。
